# 手动部署、数据库迁移与回退

## 手动部署

此过程适合已经有宝塔、MySQL 或其他业务的服务器。不要运行会替换整机数据库的软件包卸载或重装命令。

1. 从 GitHub Releases 下载当前签名发行包。使用发布的 SHA-256 检查文件；安装脚本还会验证内置公钥对应的 Ed25519 签名。
2. 将包解压到 /opt/forward-panel。建立专属系统用户 forward-panel，shell 为 nologin。
3. 建立该用户拥有的 /var/lib/forward-panel 和 runtime 子目录，权限 0700。移除发行包内空 state 目录，创建 state 指向私有目录的软链接。
4. 配置独立 MariaDB 数据库及只能访问该数据库的用户。若现有 MySQL 不可修改，可单独启动 MariaDB 到 127.0.0.1:3307，使用不同的数据目录、套接字与服务名。
5. 创建私有 controller.json，示例如下。实际密码随机生成，禁止把这个文件放到网站公开目录。

~~~json
{
  "driver":"mysql",
  "listen":"0.0.0.0:19280",
  "origin":"http://服务器公网IP:19280",
  "socket":"/opt/forward-panel/state/runtime/admin.sock",
  "controller_urls":[],
  "panel_ips":["服务器公网IP"],
  "mysql":{
    "host":"127.0.0.1","port":3307,
    "name":"forward_panel","user":"forward_panel",
    "password":"替换为数据库随机密码"
  },
  "payment":{
    "enabled":false,"version":"v1","gateway":"",
    "merchant_id":"","secret":"",
    "public_origin":"http://服务器公网IP:19280",
    "methods":[{"id":"alipay","name":"支付宝","type":"alipay","enabled":true}]
  }
}
~~~

6. 新面板通过二进制的 --install 初始化。它从标准输入读取 JSON，避免密码出现在命令参数或历史中。创建仅 root 可读的 /etc/forward-panel/initial-admin.json，内容为 {"name":"站点名称","username":"admin","password":"至少12字节随机密码"}，然后运行：

~~~bash
cat /etc/forward-panel/initial-admin.json | runuser -u forward-panel --   /opt/forward-panel/bin/controller-linux-amd64   -config /opt/forward-panel/state/controller.json --install
~~~

arm64 请替换二进制名称。已有账户时初始化会拒绝覆盖。私有 controller.json 必须为 forward-panel 所有，权限 0600。

7. 配置运行实例：

~~~bash
python3 /opt/forward-panel/ops/manage.py configure http://服务器公网IP:19280 19280
ln -s /opt/forward-panel/manage.sh /usr/local/bin/forward-panel
~~~

8. 按反向代理文档配置 HTTPS，并通过菜单设置 HTTPS 地址。

## PHP / Go 旧版迁移

先在独立服务器验证，再安排短暂维护窗口。

- 保存旧站点源码、Nginx 配置、控制服务单元和完整 state。必须保留 app.key，否则支付、SMTP、二步验证等加密内容无法解密。
- 停止旧面板写入及旧主控后再做最终数据库导出；保留节点 token 哈希、账单、累计报告游标、租约与端口记录。
- 导入到独立 MariaDB，不直接覆盖共享 MySQL。修改新 controller.json 的数据库连接、socket 路径和域名；复制旧 app.key。
- 已有数据库不运行 --install，原管理员密码与权限保持。
- 启动 Rust 服务，确认健康后将该域名的 Nginx location / 指向 Rust；停止的只是旧站点自己的 PHP 和 Go 服务，其他站点不修改。
- 主控协议保持兼容。通过后台重新部署已有节点可升级 Rust Agent，保留其身份与未确认流量日志。不要当作新节点重复添加。
- 核对账户、套餐、流量、端口、支付和邮件，实际测试 TCP / UDP 与达量暂停，再结束维护。

旧 Go 服务、PHP 源码与原数据库只作为回退快照保存，勿与新主控同时处理同一组节点和订单。

## 域名变更

先让新域名 HTTPS 可访问，再修改私有配置中的 origin、payment.public_origin 和 controller_urls。controller_urls 的新 WSS 地址放在第一项，保留有效旧地址作为过渡。在线 Agent 接收新地址后自动持久化并重连。

旧主控已不可达的节点无法接收推送；使用后台“重新部署”输入该服务器 SSH 信息，重新写入当前主控地址。SSH 密码仅用于这次任务，不保存到数据库。

## 手动恢复备份

停止主控后，先备份现有数据库与状态。只解压自己创建且可信的 root 私有备份，不以 root 解压不可信归档。

备份含 database.sql、state、config 与服务单元。向专属数据库导入 database.sql；恢复 state 的私有文件和 SSH 指纹，恢复所有权为 forward-panel，目录 0700 / 文件 0600。恢复相应程序版本和服务配置，再检查 Nginx 并启动主控。

在线节点可能在维护期间保留尚未确认的流量；保留节点私有 traffic.json，恢复后依靠周期与序号去重，不要清空它。
