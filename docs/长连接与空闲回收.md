# 长连接与空闲回收

0.3.8 更正 TCP 空闲时间的计算方式。旧逻辑分别对两个方向设置 300 秒读取超时；持续下载时，上传方向可能长期没有应用数据，反之亦然，因此仍在传输的连接可能被安静方向的超时关闭。

现在同一条 TCP 转发的两个方向共享单调时钟活动记录，成功读取或写入数据都会推进记录。旧截止时间到达时重新检查双向活动；仍有传输就继续等待，只有两个方向均无应用数据进展达到 300 秒才按原有空闲策略回收。使用每连接的原子时间戳，不新增独立后台任务或业务定时轮询。

TCP 的 ACK 和内核保活报文不属于应用数据。本更新保留真正空闲连接的回收，也保留原有写入阻塞超时、主控授权期限、套餐限额、错误回收和规则取消行为。正常半关闭、慢速读取与 0.3.7 的复位处理继续有效。

测试包括短时共享空闲截止时间验证，以及两条实际 TCP 连接同时连续上传和下载超过 300 秒、安静方向不额外发送应用保活数据的验证；完成后检查全部数据、连接计数、套餐额度和计量。具体执行结果见 [验收记录](验收.md)。

排查连接问题时，需区分本地监听失败、目标连接拒绝或超时、应用协议认证失败、套餐或主控授权暂停，以及网络中断。端口监听和配置确认成功，不代表目标应用已经通过用户协议认证；不要通过放宽配额、关闭校验或修改对外显示地址来掩盖目标故障。
