# 0.3.2 验收记录

验证日期：2026-10-09。开发、构建与测试在开发服务器完成，真实网络测试使用独立测试被控。生产升级另做备份和回归核对。以下记录只覆盖实际执行范围，不代表不存在漏洞。

## 套餐限额与已有租约更新

- 14 个 Rust 测试通过：7 个单元测试，MariaDB 兼容、租约生命周期、限额真实网络、规则迁移各 1 个集成测试，以及 3 个原有网络测试。格式检查和 Clippy 全目标无警告，前端 TypeScript 检查与构建通过。
- 额度协调器验证延迟确认、主控状态持久化/重载、预留过期和降低连接上限。2500 步、7 个模拟节点的随机确认顺序测试检查跨节点预留总量不会重复分配。
- 在同一台真实测试服务器上运行两个独立 WSS Agent 实例：多个端口、两个节点共享同一已购套餐的 TCP 和 UDP 上限；释放 TCP 后容量可被其他节点使用。
- 实际降低 TCP 上限时，已建立连接继续传输，超额期间阻止新增转发连接。多个端口、双向传输共用带宽额度，连续配置刷新不会额外补发流量令牌。
- 持续双节点传输共 16 MiB 应用载荷，上行与下行合计设置 8 Mbps，18.412 秒完成，平均 7.290 Mbps，内容一致。此项验证限速和短时稳定性，不是长期运行或公网带宽承诺。
- 普通编辑保留已购额度；强制更新同步带宽、TCP、UDP、端口、流量和节点，保留已用流量、到期日、自然重置日和计费周期。
- 实测强制缩减端口及移除节点的具体释放规则清单、流量达量暂停及提高额度后恢复；预览期间修改目标后，旧确认返回 409，数据未被部分更新。
- 缺少预览、篡改凭证、确认参数变化、非管理员、CSRF 错误均被拒绝。旧接口省略新增字段时保留已设置的限额；明确填写 0 才取消该项限额。
- 浏览器检查 40 个桌面和手机页面，无脚本异常、HTTP 5xx 或页面横向溢出。实际完成已有租约强制更新，重新预览会清除已勾选确认，用户端显示更新后的额度。
- 官方 AnyTLS 参考服务配合 Mihomo 客户端，连续完成 6 次 1 MiB 内容一致性传输；未使用真实客户的连接密码。
- amd64 和 arm64 静态二进制均构建完成。实机运行验收为 amd64，arm64 尚未在独立硬件测试。

## 安全与主控负载

检查私有文件路径、路径穿越、Host、请求体/请求头/URI 大小、匿名越权、登录限速、WSS 认证与跨站拒绝、慢请求头超时，均符合预期。人工审查新增预览摘要、数据库事务、额度确认编号及重连预留逻辑。

200 个并发客户端向管理状态接口发送 600 次请求，1.676 秒完成：128 次 HTTP 200、472 次 HTTP 429，无 HTTP 5xx 或进程崩溃；P95 为 1447.01 毫秒。约 357.9 次/秒包含限流响应，不能当作成功业务吞吐量。测试当时同时进行发行构建，不作为独占硬件基准。

npm 全依赖审计为 0 项已知漏洞；Gitleaks 源码检查为 0 项凭据泄漏。RustSec 数据库提交为 550efd3d587a29b2e2c2b21b17a440da4fede999，仍报告 RUSTSEC-2023-0071，涉及 rsa 0.9.10 与 0.10.0-rc.18，未新增依赖告警。上游仍无修复版本，使用路径及限制见 [SECURITY.md](../SECURITY.md) 和 [RustSec 公告](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)，不宣称零漏洞。

支付、邮件和未修改功能沿用 [0.3.1 验收](验收-0.3.1.md) 与 [0.3.0 验收](验收-0.3.0.md)；本次未向真实商户付款或向真实用户发送测试邮件。重连预留最多保守保留约 30 秒，其间部分受限套餐可能暂时没有可用额度，详见[限额说明](套餐限额与变更预览.md)。

## 不限速转发回归

最终版针对 16 条并发 TCP 做两轮交替顺序的回环复测；引擎、收发端分别固定在不同 CPU 核心，测试时未进行编译：

| 版本 | 平均接收吞吐 | 引擎平均 CPU（单核） | 峰值 RSS |
| --- | --- | --- | --- |
| 0.3.1 | 7.36 Gbps | 97.93% | 2.07 MiB |
| 0.3.2 | 7.43 Gbps | 97.86% | 2.07 MiB |

不限速路径直接发送，启用带宽限制时才进入异步令牌等待。此次复测未见此前候选版的并发 TCP 额外开销；数值有虚拟化环境与调度波动，不代表固定提升、公网性能或长期稳定性承诺。首轮回归还覆盖单 TCP、反向 TCP 和 UDP 200/600 Mbps，未出现进程崩溃或内存失控。

发行包校验包括 ELF 架构、每个文件的 SHA-256、主控与 Agent 清单的 Ed25519 签名，以及解压后的凭据扫描。真实应用密钥、SSH 密码、Agent 令牌及验收登录凭据不进入发行包。
