# 多网卡监听

0.3.6 起，通过面板部署或更新的转发节点默认使用 `0.0.0.0` 监听 TCP 与 UDP，覆盖服务器所有 IPv4 网卡。默认路由上的 IP 只用于识别出口及采集网卡信息，不再限制入口。

## 地址与端口

“对外显示连接 IP”仍是提供给用户的访问地址，可以是上游映射地址，不必是服务器网卡实际拥有的 IP。监听地址由 Agent 使用，两者互相独立。此更新不修改对外地址、目标、已购套餐、流量用量或端口编号。

同一端口仍是一组 TCP+UDP。全部网卡共用该分配和套餐额度，不会按网卡重复计算端口数量；同时从不同本机 IP 访问的连接仍按实际连接计入额度。

UDP 使用 Linux 的 IP_PKTINFO 获取每个报文的目的本机地址，回包选择同一地址作为源地址。相同客户端同时连接两张网卡时分别保存会话，避免响应地址错乱。Agent 仍使用普通服务账户，不增加 root 权限或网络管理能力。

## 旧节点升级

1. 先更新主控至 0.3.6 或更新版本。
2. 在管理后台检查 Agent 版本并更新节点。
3. 新 Agent 通过 WSS 上报后，主控将旧默认监听地址对应的端口池和未释放规则迁移至 `0.0.0.0`。
4. 核对 Agent 的实际监听确认，再测试原来的用户入口。

升级会重启 Agent，并重新绑定受影响规则，现有连接需要重连。请在维护时段操作。无需重新创建套餐或端口规则。

如果曾在同一节点的不同本机 IP 上重复使用同一端口，改为所有网卡监听后会发生冲突。主控会拒绝这次监听地址迁移；请先调整重复端口，再重试。端口池、随机分配、自定义端口和规则导入均检查通配监听与指定地址之间的冲突。其他应用占用该端口时 Agent 会返回真实监听错误。

## 范围

本次默认监听覆盖 IPv4。原有明确 IPv6 地址的规则继续支持；不将 `0.0.0.0` 描述为双栈监听。

程序不会改动宿主机默认路由、策略路由、NAT 或防火墙。上游端口映射及安全组仍需将连接送到正确网卡；多出口环境如需策略路由，由服务器管理员配置。监听和握手正常只证明入口已接入，目标服务的协议、证书及用户认证仍需单独正确配置。
